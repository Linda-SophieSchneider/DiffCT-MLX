API Reference

diffct_mlx is the unified, auto-backend API most users should import. diffct_mlx.engine is the Torch/numba-CUDA engine it wraps on the Torch backend, a maintained copy of upstream diffct 2.5.2.

The unified package: diffct_mlx

Backend

diffct_mlx.backend selects the compute engine at import time (torch or mlx; override with DIFFCT_BACKEND). dct.backend is the chosen name. The backend-neutral array namespace diffct_mlx.backend.xp mirrors mlx.core on both engines and is what all shared reconstruction code is written against.

Conventions (diffct_mlx.conventions, re-exported at top level)

Since 3.0 every projector places detector pixel i at det_center + (i - (N-1)/2)·du and returns physical line integrals (µ · length). DETECTOR_CONVENTIONS is ("centered", "legacy") and LINE_INTEGRAL_UNITS is ("physical", "voxel"). The operator factories take detector_convention= and line_integrals=; kernel_detector_center(det_center, det_u_vec, du, det_v_vec, dv, convention="legacy") converts a 2.x detector centre for direct calls and line_integral_scale gives the unit factor. See Migrating from 2.x to 3.0.

Projectors (diffct_mlx.projectors, re-exported at top level)

Functional operators with identical signatures on both backends: parallel_forward / parallel_backward, fan_forward / fan_backward, cone_forward / cone_backward, and the separable-footprint variants *_forward_footprint / *_backward_footprint (cone_backward_footprint additionally accepts indices= for sparse region-of-interest evaluation). All flow gradients to their data. Siddon forward projectors also flow exact gradients to the geometry arrays on the Torch backend; on MLX this holds for cone Siddon, while fan and parallel geometry gradients are not implemented yet.

Geometry (diffct_mlx.geometry, re-exported at top level)

Trajectory generators: circular_trajectory_3d, spiral_trajectory_3d (helical), sinusoidal_trajectory_3d, saddle_trajectory_3d, random_trajectory_3d, custom_trajectory_3d, laminography_trajectory_3d, plus the 2D fan/parallel counterparts and load_arbitrary_cone_geometry_from_json for measured-scan geometry files.

Operator algebra (diffct_mlx.operators)

LinearOperator with A @ x, A.T, composition, sums and scaling; ProjectionOperator with .subset(views) for ordered-subset methods; builders make_parallel_2d_operator, make_fan_2d_operator, make_cone_3d_operator (choose projector_mode="siddon" or "footprint"). IdentityOperator, DiagonalOperator, FunctionOperator compose into pipelines; everything stays differentiable.

Functionals & denoisers (diffct_mlx.functionals, diffct_mlx.filters)

Objectives/regularizers/constraints: SquaredL2, Tikhonov, L1Norm, LpNorm, Huber, TotalVariation, AdaptiveWeightedTV, NonNegativity, Box, soft_threshold; edge-preserving denoisers Bilateral, Guided, Median, HistogramSparsity, Azimuthal, DictionarySparsity and RegularizerSequence for Plug-and-Play priors.

Reconstruction (diffct_mlx.reconstruction_algorithms, re-exported at top level)

Analytic: reconstruct_fbp / reconstruct_fdk (+ FBPParameters / FDKParameters) and reconstruct_case_fdk for a case’s quantitative physical FDK path. Iterative: reconstruct_sart / reconstruct_sirt (+ normalized SART), reconstruct_tv_pocs / reconstruct_asd_pocs / reconstruct_awtv_pocs, reconstruct_dart. Case builders bundling data + matched operators: build_parallel_2d_case, build_fan_2d_case, build_cone_3d_case, build_measured_cone_3d_case, build_npy_cone_3d_case. Solver registry: reconstruct(name, A, b, ...), register_algorithm, list_algorithms with landweber, cgls, pcg, ls / wls / rls / rwls, dls / rdls, mlem / osem, mltr.

Quantitative FDK and units

Cone-beam cases expose fdk_weight, fdk_filter and fdk_back_project when the active backend provides the physical FDK gather path. reconstruct_case_fdk(case) combines cosine weighting, trapezoidal per-view angular weights, a zero-padded physical ramp and the voxel-driven (SID/U)^2 backprojector; its result is attenuation in 1/mm.

Projectors return physical line integrals, so A @ x is already in µ · mm when x is in 1/mm. simulate_scan feeds them straight into the transmission and beam-hardening physics. Iterative reconstruction of a physical sinogram returns attenuation in 1/mm. Operators built with line_integrals="voxel" reproduce the 2.x voxel units; their to_physical attribute is the factor back to physical units.

Physics & simulation (diffct_mlx.physics)

Corrections: flat_field, ring_removal, bad_pixel_correction, beam_hardening_polynomial, detector_deblur, scatter_correction, mar_inpaint and the composable PreprocessingPipeline. Simulation: Spectrum, simulate_scan, apply_beam_hardening, add_poisson_noise; embedded spectrum library physics.spectra (tube_spectrum, material_attenuation, preset, 40–225 kVp).

Sinogram-domain tools (diffct_mlx.rebinning)

apply_parker_weighting (short scans), apply_offset_weighting (extended FOV), extend_truncation, fan_to_parallel, curved_to_flat / flat_to_curved.

Phantoms & calibration (diffct_mlx.phantoms, diffct_mlx.calibration)

shepp_logan_2d / shepp_logan_3d voxel phantoms; the analytic engine Ellipsoid / Phantom / shepp_logan_phantom with exact closed-form cone projections for ground truth. Self-calibration: estimate_center_of_rotation, refine_center_by_sharpness, apply_center_offset.

Out-of-core & multi-GPU (diffct_mlx.orchestration; CUDA only)

chunked_cone_forward / chunked_cone_backward / chunked_cone_fdk, chunked_sirt, chunked_os_sart, mgpu_cone_forward / mgpu_cone_backproject / mgpu_sirt, storage helpers open_memmap / open_zarr / set_out_of_core_dir / set_out_of_core_backend, and the shadow-geometry primitives row_range_for_zslab / slice_range_for_vband.

The Torch engine: diffct_mlx.engine

The engine is upstream diffct 2.5.2, vendored and maintained in DiffCT-MLX. Its modules can be used directly on the Torch backend:

  • diffct_mlx.engine.operators – Projector: chunked, streamed projection for parallel, fan, cone and parallel3d beams, per-axis voxel spacing, detector surfaces, batch dimensions and multiple GPUs

  • diffct_mlx.engine.backends – backend selection ("numba" native CUDA, "torch" portable on CPU, CUDA, ROCm and MPS) and precision="fast" | "float32" | "float64"

  • diffct_mlx.engine.projectors – PyTorch autograd.Function projectors and backprojectors with exact geometry gradients

  • diffct_mlx.engine.footprint – separable-footprint autograd Functions, including the sparse cone backprojection (DiffCT-MLX extension)

  • diffct_mlx.engine.geometry – trajectory generators for 2D and 3D scans

  • diffct_mlx.engine.analytical – ramp filter, cosine and Parker weights, voxel-driven FBP/FDK backprojection

  • diffct_mlx.engine.reconstruction and solvers – differentiable fbp, fdk, helical_fdk and cgls, sirt, tv_reconstruction

  • diffct_mlx.engine.surfaces – ParameterizedSurface for curved detectors

  • diffct_mlx.engine.kernels – numba-CUDA kernels for advanced users

  • diffct_mlx.engine.utils and constants – device helpers and launch constants

The upstream user documentation of the engine ships in docs/engine/ of the repository.

class diffct_mlx.engine.Projector(trajectory, volume_shape, detector_shape, *, beam='cone', detector_spacing=1.0, voxel_spacing=1.0, devices=None, distributed=False, process_group=None, detector_surface=None, volume_chunk_shape=None, view_chunk_size=None, detector_chunk_shape=None, schedule='auto', partition='views', backend='auto', precision='fast', partition_grid=None, native_volume_layout=False)[source]

Bases: object

Project floating tensors along parallel, fan, cone, or parallel3d trajectories.

A parallel trajectory is (ray_dir, det_origin, det_u) and a fan trajectory is (src_pos, det_center, det_u); each component has shape (views, 2). A cone trajectory is (src_pos, det_center, det_u, det_v) with components shaped (views, 3). A parallel3d trajectory is (ray_dir, det_center, det_u, det_v) with the same 3D component shapes; its infinite ray lines pass through detector pixels. Direction axes are unit vectors; parallel ray_dir and det_u and 3D detector det_u and det_v are orthogonal. Parallel3d rays can be oblique but must not be tangent to the detector plane. If no trajectory tensor requires gradients, the projector clones the geometry. Otherwise it keeps references, reads the current values at every call, and returns gradients for those tensors. Live default frames and overrides are checked on each call. project, backproject, __call__ and their *_into variants accept a keyword-only trajectory replacing all frames for that call. It must retain the constructor’s beam and view count; it is validated and snapshotted independently without replacing the default frames. Rebuild computed trajectories from trainable leaves on each optimization step. Second derivatives are available for volumes and sinograms, not for the geometry.

detector_surface(u, v) optionally supplies local (u, v, n) offsets for every pixel. It receives centred physical float64 grids on CPU and returns a floating-point tensor shaped (*detector_shape, 3) or (views, *detector_shape, 3). 3D normals are cross(det_u, det_v); 2D normals are (det_u_y, -det_u_x) with zero middle offsets. Offsets can be on CPU or CUDA in full-volume and streamed execution. World points expand on each compute device after view sharding. Native execution preserves the composition’s dtype promotion before converting complete coordinates to float32. The PyTorch backend uses the selected precision. The callback is sampled and validated on every call, with first-order gradients for captured PyTorch parameters. Omitting it preserves the flat detector.

ParameterizedSurface(sampler, parameters) instead samples only the selected global view IDs and detector rectangle. Its explicit parameters and trajectory values are snapshotted once per call, with batch-local first-order parameter gradients. detector_chunk_shape bounds pixel rectangles; their physical origins remain those of the full detector.

Volumes use (H, W) for parallel and fan beams and (D, H, W) for cone and parallel3d beams. Sinograms use (views, detectors) or (views, U, V). Any leading batch/channel dimensions are preserved. voxel_spacing is a positive scalar or a tuple in volume tensor order: (y, x) or (z, y, x). Physical coordinates retain the centred global volume frame. Results stay on the input device. precision="fast" and "float32" return float32; "float64" computes geometry, ray lengths and accumulations in float64. The selected backend, precision and dtype are public metadata.

backend="auto" selects the native "numba" backend for NVIDIA CUDA and fast precision with scalar or per-axis voxel spacing, except for hybrid partitions. Other configurations use portable "torch" execution on the input’s CPU or supported PyTorch accelerator. Explicit "numba" requires a compatible native configuration. Data torch.func transforms use portable operations while preserving selected metadata.

Native CPU inputs stream spatial tiles and view batches through CUDA. Native CUDA inputs retain the full-volume path when its additional working set fits every device; otherwise they stream too. volume_chunk_shape sets explicit spatial limits in tensor order; view_chunk_size sets an explicit view limit. Either forces native streaming. Native automatic sizing uses live free memory, reusable allocator cache and the observable per-process fraction ceiling, retaining 25% headroom. Automatic sizing compares fitting first-axis slabs and Cartesian blocks; view batches are at most 32 and shrink if needed. Older PyTorch without a public fraction getter cannot account for that ceiling. Concurrent external allocations can still cause an allocation error.

For the native backend, schedule="auto" selects spatial, view or bounded two-tile window order using estimated full-workload time from short native pilots, with estimated copy bytes breaking ties. The same orders can be requested with "spatial", "views" or "window"; capacity may require a serial spatial fallback. Streaming uses distinct upload, compute and download streams and two reusable host slots capped at 8 MiB each. Store reads and completed output drains are fragmented independently of the resident GPU tile size. last_execution_stats reports actual copy payloads, native launches/layouts, planned capacity and pilot metadata; it is None before execution, after errors, and on the uninstrumented native full-CUDA path. Each thread reads the report of its own last call; backward reports go to the thread that ran the forward call. Portable execution reports actual ray/tile pairs, store I/O, transfers and collective payloads, with conservative automatic chunks targeting 8 MiB work arrays. Explicit chunk hints take priority. Reports and selection caches retain metadata.

native_volume_layout=True makes native full-CUDA cone and parallel3d backprojections of unbatched inputs on a flat detector return (D, H, W) tensors with the kernels’ (W, H, D)-contiguous strides instead of contiguous copies; native projections accept such tensors without a copy. An iterative solver that keeps its volumes in this layout then avoids two whole-volume copies per normal-operator application on one device. The layout does not change the operator. Results from several local devices, curved detectors, batched inputs, streamed execution and the PyTorch backend still involve copies.

Full host volumes/sinograms stay on CPU; streamed native CUDA buffers are bounded by the chosen tile and view batch. Caller-owned CUDA data/results and CUDA work inside a supplied callback are outside this memory bound. Native local devices launch their view batches concurrently, but each device receives every owned volume tile, so host transfers limit the speedup. Local devices split views in list order. partition="views" returns rank-local projections and replicated backprojections. partition="space" assigns balanced first-axis slabs and returns replicated projections and owned backprojections. partition="hybrid" combines both with partition_grid=(view_ranks, space_ranks) and parent-group rank view_rank * space_world_size + space_rank. global_volume_shape is the constructor shape; volume_slice identifies the owned global slab, and volume_shape and local_volume_shape give its required tensor shape. Empty slabs are valid. Physical coordinates retain the global volume frame. For replicated outputs, count the loss once globally or divide each rank’s projection loss by space_world_size or backprojection loss by view_world_size. Geometry gradients already SUM over all parent ranks; do not apply an additional DDP reduction to them. Space ranks participate in backward even when their local input and geometry require no gradients.

Summary

PyTorch autograd function for differentiable 2D parallel beam forward projection.

Notes

Provides a differentiable interface to the CUDA-accelerated Siddon ray-tracing method with a cell-constant image basis for parallel beam CT geometry. The forward pass computes the sinogram from a 2D image using parallel beam geometry. The backward pass computes gradients using the adjoint backprojection operation. Requires NVIDIA CUDA hardware. Geometry tensors are moved to the image’s device; execution uses float32.

Examples

>>> import torch
>>> from diffct import ParallelProjectorFunction, circular_trajectory_2d_parallel
>>>
>>> image = torch.randn(128, 128, device='cuda', requires_grad=True)
>>> ray_dir, det_origin, det_u_vec = circular_trajectory_2d_parallel(180, device='cuda')
>>> sinogram = ParallelProjectorFunction.apply(image, ray_dir, det_origin, det_u_vec, 192, 1.0)
>>> sinogram.sum().backward()
>>> image.grad.shape
torch.Size([128, 128])
static backward(ctx, grad_sinogram)[source]

Define a formula for differentiating the operation with backward mode automatic differentiation.

This function is to be overridden by all subclasses. (Defining this function is equivalent to defining the vjp function.)

It must accept a context ctx as the first argument, followed by as many outputs as the forward() returned (None will be passed in for non tensor outputs of the forward function), and it should return as many tensors, as there were inputs to forward(). Each argument is the gradient w.r.t the given output, and each returned value should be the gradient w.r.t. the corresponding input. If an input is not a Tensor or is a Tensor not requiring grads, you can just pass None as a gradient for that input.

The strides of the gradients passed to backward() are undefined: they are not guaranteed to be contiguous or to match the strides of the corresponding forward outputs, so implementations must not assume a particular memory layout.

The context can be used to retrieve tensors saved during the forward pass. It also has an attribute ctx.needs_input_grad as a tuple of booleans representing whether each input needs gradient. E.g., backward() will have ctx.needs_input_grad[0] = True if the first input to forward() needs gradient computed w.r.t. the output.

diffct_mlx.engine.analytical.angular_integration_weights(angles, redundant_full_scan=True)[source]

Trapezoidal per-view integration weights for the analytical FBP/FDK sum.

For a full 2*pi scan, each redundant ray is sampled twice so the classical FBP/FDK formula carries a 1/2 redundancy factor. When redundant_full_scan=True (the default) this factor is baked into the returned weights: they sum to pi over a uniform full scan, which is exactly what a voxel-driven gather backprojector with the (sid/U)^2 weight needs to produce a unit-amplitude reconstruction.

Short scans retain their actual angular range; the Parker window handles their redundancy at the sinogram-filtering stage. Leave redundant_full_scan=True for automatic fan/cone scan classification. Setting it to False explicitly disables the full-turn 1/2 factor.

Angles are in radians and weights are returned in input order. For a short scan wrapped modulo 2*pi, the gap outside the acquisition must be clearly more than twice every other gap. If the sorted range looks like a full turn, that isolated gap marks the scan boundary instead. A full turn with a similarly large missing sector is ambiguous from angles alone. Pass continuous (unwrapped) angles to parker_weights. FP16 and BF16 angles are promoted to FP32; FP64 angles retain their precision.

Ramp Filter Options

ramp_filter_1d is a generic 1D ramp filter used by every analytical reconstruction example. Its call signature is:

ramp_filter_1d(sinogram_tensor, dim=-1, sample_spacing=1.0,
               pad_factor=1, window=None, use_rfft=True)
sample_spacing

Physical detector-cell spacing along dim (e.g. du for the cone-beam case). The filter is rescaled by 1 / sample_spacing internally so the output is in physical units and the reconstruction amplitude stays calibrated when detector pitch changes. Pass 1.0 to reproduce sample-unit behaviour.

pad_factor

Zero-pad the signal to pad_factor * N samples along dim before the FFT. Common values:

  • 1 (default): no padding, fastest but prone to circular convolution wrap-around at the detector edges.

  • 2: recommended for cone-beam FDK, good trade-off.

  • 4: stricter padding for objects close to the detector edge.

window

Frequency-domain apodization multiplied onto the bare Ram-Lak ramp:

  • None or "ram-lak": unwindowed Ram-Lak, sharpest, highest noise.

  • "hann" / "hanning": Hann window, strong high-frequency suppression.

  • "hamming": slightly milder than Hann.

  • "cosine": half-cosine rolloff.

  • "shepp-logan": sinc rolloff, classical choice.

Use torch.fft.rfft / irfft when the input is real. Defaults to True; set to False only if you need the complex FFT path.

Analytical FBP / FDK architecture

Each of the three analytical backprojection helpers (parallel_weighted_backproject, fan_weighted_backproject, cone_weighted_backproject) dispatches to a dedicated voxel-driven gather kernel, separate from the Siddon-based ray-driven scatter kernels that drive autograd. The autograd kernels are the pure adjoints P^T of the forward projectors (no distance weighting, no magnification scale), so the autograd classes form self-consistent forward / backward adjoint pairs. The analytical helpers on top apply the appropriate FBP / FDK distance weighting and the analytical scale so the returned image is already amplitude-calibrated.

Scale factors applied inside the analytical helpers:

  • parallel_weighted_backproject multiplies by 1 / (2 * pi) (Fourier-convention constant; parallel beam has no source and no magnification so there is no (sid/U)^2 weight).

  • fan_weighted_backproject applies a per-voxel (sid_n / U_n)^2 weight inside the gather kernel and a sdd_mean / (2 * pi * sid_mean) scale on top.

  • cone_weighted_backproject applies a per-voxel (sid_n / U_n)^2 weight inside the gather kernel and a sdd_mean / (2 * pi * sid_mean) scale on top.

sid_n and U_n are measured in the per-view detector-normal direction. For a canonical circular orbit sid_n reduces to the classical scalar sid, and U_n to the classical sid + x * sin(beta) - y * cos(beta). For non-circular trajectories (spiral, saddle, random) the helpers keep working by computing the per-view quantities directly from the trajectory arrays; the result is the standard heuristic generalisation of FDK beyond the circle.

Usage Notes

  • The autograd Functions run the native kernels on CUDA tensors. Projector with backend="torch" also runs on CPU, MPS and ROCm tensors, and the unified diffct_mlx Siddon projectors pick that path automatically for non-CUDA tensors.

  • Geometry helper functions build the ray_dir, det_origin, and detector orientation vectors expected by the projector operators.

  • Gradients flow through both forward and backward passes; set requires_grad=True on inputs that participate in optimisation loops.

  • Ensure tensors are contiguous and use consistent dtype (torch.float32) for maximum kernel performance.
